# การเข้าประชิดและแบ่งจังหวะโจมตีของ Enemy

## เป้าหมายในการออกแบบ
ระบบเดิมต่างกันที่ตำแหน่งปลายทางและการหลบกัน แต่ทุกตัวยังมีเหตุผลเดียวคือเดินเข้าระยะแล้วตี การเพิ่มความสุ่มอย่างเดียวจึงไม่แก้พฤติกรรมของฝูง แนวทางใหม่นี้แยกการเลือกวิธีเข้าหาของแต่ละตัวออกจากการจัดสิทธิ์โจมตีของกลุ่ม เพื่อให้เกิดทั้งความหลากหลายและช่องว่างที่ผู้เล่นอ่านสถานการณ์ได้

## การเลือกวิธีเข้าหา
- Direct: เดินกดดัน ใช้ Pressure Speed Multiplier ปรับความเร็วไล่ช่วงที่ยังอยู่นอกระยะชะลอ
- Flank: เข้าด้านข้างตาม Flank Angle โดยคำนวณจากฝั่งที่ศัตรูอยู่ตอนเลือกวิธี ตรวจ NavMesh และ path ก่อนใช้จุดใหม่
- Burst: เร่งเข้าหาตาม Burst Speed Multiplier ในช่วงไกล แล้วชะลอตามระบบเดิมเมื่อเข้าใกล้

เลือกเฉพาะช่วงเห็นผู้เล่นและยังไม่โจมตี ใช้ Direct / Flank / Burst Weights เป็นน้ำหนักสัมพัทธ์ เช่น 1/1/0.6 หมายถึง Burst มีโอกาสน้อยกว่าสองวิธีแรก ทุกค่าเป็นศูนย์ใช้ Direct การตัดสินใจยึดไว้ตาม Decision Interval ไม่สุ่มทุกเฟรม และไม่เปลี่ยนวิธีระหว่างท่าโจมตี

ตอนมองไม่เห็นใช้ตำแหน่งล่าสุดที่เห็นและวงจร Search เดิม ไม่มีการรู้ตำแหน่งผู้เล่นจากข้อมูลของเพื่อนอัตโนมัติ

## การตัดสินใจร่วมกัน
EnemyAttackCoordinator เก็บ reservation แยกตาม target ของ PlayerController จริง โดยมีจำนวนจำกัดตาม Maximum Reserved Attackers

1. ศัตรูที่เห็นผู้เล่น อยู่ใน Engagement Distance ไม่ติด cooldown และพ้นช่วงพัก ขอสิทธิ์เข้าประชิด
2. ตัวได้สิทธิ์เข้าไปโจมตี ส่วนตัวที่ไม่ได้สิทธิ์อยู่ในสถานะ Pressure และหาจุดบนวง Pressure Ring นอก Attack Range
3. สิทธิ์ครอบคลุมการเข้าหา การเตรียมโจมตี hit delay และ cooldown recovery ตัวที่จองอยู่จึงไม่เปิดช่องให้ทั้งฝูงตีทับกัน
4. เมื่อโจมตีจบ ถูกยิงเสียจังหวะ Pause ตาย หรือ Disable จะคืนสิทธิ์ และพักตาม Rest Before Next Turn ก่อนขอใหม่
5. หากจองแล้วเข้าไม่ถึงภายใน Attack Turn Timeout จะคืนสิทธิ์ ป้องกันตัวติดทางตันครองสิทธิ์ตลอด
6. Reservation ที่หยุดอัปเดตมีเวลาหมดอายุ และข้อมูล static ล้างเมื่อเริ่ม Play ใหม่เพื่อรองรับการปิด Domain Reload

ตัวที่ไม่ได้สิทธิ์ยังหลบและแยกจากเพื่อนด้วย Crowd Separation เดิม หากจุดวงกดดันไม่มี path จะรอในจุดที่ไปถึงได้ ไม่ผลักผ่านผนังและไม่เร่งเข้าตีแทนเอง ระบบยังไม่มีคิวที่รับประกันลำดับก่อนหลังแบบ FIFO การพักหลังจบและ timeout ช่วยเปิดโอกาสให้ตัวอื่น และยังต้องปรับจาก playtest ฝูงจริง

## วิธีตั้งค่า
เปิด Enemy Profile หรือ Enemy Lab แล้วดู Approach Decisions และ Group Engagement ทุกช่องมี Tooltip ภาษาอังกฤษ

ค่าตั้งต้นสำหรับลองฝูงเล็ก:
- Use Approach Decisions: เปิด
- Decision Interval: 2.5 วินาที
- Direct / Flank / Burst Weights: 1 / 1 / 0.6
- Flank Angle: 40 องศา
- Pressure Speed Multiplier: 0.7
- Burst Speed Multiplier: 1.25
- Coordinate Attacks: เปิด
- Maximum Reserved Attackers: 1 เพื่ออ่านจังหวะง่าย; 2 เพื่อเพิ่มแรงกดดัน
- Engagement Distance: 6 หน่วย
- Pressure Ring Radius: 3.5 หน่วย ระบบบังคับให้อยู่นอก Attack Range
- Attack Turn Timeout: 4 วินาที
- Rest Before Next Turn: 1 วินาที

ใช้ limit เดียวกันสำหรับ profiles ที่เจอผู้เล่นใน encounter เดียวกัน หากใช้ต่างกัน ผู้ขอใหม่จะใช้ค่าจำกัดที่เข้มกว่าของ reservation ที่มีอยู่ แต่จะไม่ยกเลิกท่าโจมตีที่เริ่มแล้วเพื่อบังคับ limit ใหม่

ปิด Coordinate Attacks เพื่อกลับไปให้ทุกตัวเข้าตีได้ตามวงจรเดิม ปิด Use Approach Decisions เพื่อไม่เปลี่ยนวิธี/ตัวคูณความเร็ว แต่ยังเปิดการประสานกลุ่มได้แยกกัน

## ขอบเขตของงาน
ยังใช้ท่าโจมตีและระบบ Damage เดิม ไม่ได้เพิ่มคลิปพุ่ง/จับหรือ Blend Tree ใหม่ Run Animation State ที่มีอยู่ใช้ได้กับความเร็วจริงของ Agent ท่าที่เห็นจึงขึ้นกับคลิปใน Animator ด้วย

## การทดสอบ
Compile Runtime/Editor ผ่าน ทดสอบ production EnemyController และ EnemyAttackCoordinator ใน Play Mode โปรเจกต์แยก 10 checks ครอบคลุมจำกัดผู้โจมตีหนึ่งตัว, Pressure, คืนสิทธิ์เมื่อถูกยิง, รับสิทธิ์ต่อ, target คนละตัวไม่แย่งกัน, การทำ Damage ด้วย coroutine ที่เดินตามเวลาจริง และการคืนสิทธิ์เมื่อ Pause โดย PlayerController ใช้ damage stub ยังไม่ได้ยืนยัน path/animation และสมดุลฝูงใน Scenes_Gameplay จริง
