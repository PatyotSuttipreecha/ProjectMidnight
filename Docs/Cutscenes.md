# Cutscene input control

Add CutsceneController to the same GameObject as a PlayableDirector. Assign its Timeline asset and track bindings. Player is optional; empty uses an active PlayerController. In WorldTrigger > On Triggered, choose CutsceneController.Play(), rather than only PlayableDirector.Play(). Enable Trigger Once for one-shot story scenes.

Play acquires a gameplay input lock before starting Timeline. PlayerController skips movement, rotation, aim, weapon switching and Inventory input while locked. Guns and PlayerInteraction already check IsGameplayInputBlocked; Cinemachine input axis controllers are suspended without disabling the camera or CinemachineBrain. During this lock PlayerController does not apply gravity or modify animator movement parameters, allowing Timeline to own pose/placement. Configure Timeline animation/root motion separately; this controller does not repair Animation Track bindings or return a character to a designated exit position.

Finish And Release defaults to true and sets PlayableDirector wrap mode to None. When the director fires stopped (natural completion or Stop), this controller releases its own lock. Stop() can be connected to a skip UI; disabling/destroying the controller also stops its active Timeline and releases the lock. Pausing Timeline intentionally keeps the lock. On Started / On Finished are optional UnityEvents. Natural camera return requires correct Timeline/Cinemachine track setup and post-playback behavior; the controller does not change camera priorities itself.

Input locks are owner-based, so one controller cannot release another controller's lock. Inventory/document modal blocking remains independent. Play refuses to start while gameplay input is already blocked; external director Play events are also observed while the controller is enabled. Use the controller's Play method for validation and consistent lifecycle. Time.timeScale must continue running for Timeline in Game Time mode; this controller does not pause global time.

LockGameplayInput(owner) / UnlockGameplayInput(owner) are PlayerController APIs for other paired input locks. The owner must release its lock on every exit path. Enabling cutscene playback through Play On Awake can lock before Player.Start; camera inputs are rebound after Player camera initialization.

## Screen transitions
CutsceneController.Play is the shared entry point for WorldTrigger.onTriggered and DocumentPickup.onCollected. Screen Transition enables a full-screen fade overlay automatically. Fade To Black Duration controls covering the screen; Fade From Black Duration controls revealing it. Both use unscaled time. Input stays locked through entry, Timeline, and exit.
The entry covers gameplay, starts/evaluates Timeline, then reveals it. With Finish And Release, the final fade begins near the end of Timeline; bindings release under black, then gameplay is revealed. Manual Stop also uses the exit transition. On Finished runs after gameplay is revealed and the controller releases its input lock. Disabling the controller cancels transitions, removes the overlay, and releases its own lock.
Call CutsceneController.Play instead of PlayableDirector.Play for the entry fade. External direct Director playback still locks input but bypasses the entry transition. For complete custom timing, disable Use Fade and control the screen from Timeline.
